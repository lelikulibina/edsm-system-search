# План реализации MVP

План выполняется небольшими проверяемыми этапами. Основной принцип — тест сначала, затем минимальная реализация.

## Этап 1. Каркас проекта и CI
- Создать Cargo package, конфигурацию через переменные окружения и CLI-команды `serve`, `init-db`, `import`.
- Добавить GitHub Actions для `cargo fmt --check`, `cargo clippy --all-targets --all-features -- -D warnings` и `cargo test`.
- Добавить README с командами сборки и запуска.

Проверка: чистая сборка и запуск тестов в CI.

## Этап 2. Схема SQLite
- Реализовать инициализацию таблицы, B-tree индексов, R*Tree и триггеров.
- Настроить WAL, foreign_keys, busy_timeout и ограничение page cache на каждом соединении.
- Написать интеграционные тесты схемы и согласованности триггеров.

Проверка: вставка, обновление и удаление системы отражаются в R*Tree; R*Tree доступен в собранной SQLite.

## Этап 3. Поиск центральной системы
- Реализовать нормализацию и экранирование LIKE.
- Реализовать exact-first и последовательное отсечение последнего компонента.
- Зафиксировать детерминированный выбор первого кандидата.

Проверка: exact match имеет приоритет; fallback работает по уровням; неоднозначность разрешается стабильно.

## Этап 4. 3D-поиск
- Реализовать bounding-box запрос к R*Tree.
- Выполнять точный сферический фильтр по f64.
- Сортировать по расстоянию, нормализованному имени и EDSM ID.

Проверка: граница радиуса включительна; точки за пределами сферы, но внутри bounding box, исключаются; координаты с float32 округлением не теряются.

## Этап 5. Потоковый импорт
- Реализовать потоковый разбор верхнеуровневого JSON-массива.
- Добавить пакетные транзакции и UPSERT.
- Добавить статистику прочитанных, импортированных и пропущенных записей.
- Обеспечить повторный запуск без дублей.
- Не удалять записи, отсутствующие в 7-дневном дампе.

Проверка: импорт маленького JSON-массива и gzip-файла; большой массив обрабатывается потоково; повторный импорт идемпотентен; некорректная запись не ломает весь пакет.

## Этап 6. HTTP API
- Реализовать `GET /health` и `GET /search`.
- Валидировать имя, конечность радиуса, положительность и максимальный радиус.
- Перенести синхронные SQLite операции в `spawn_blocking`.
- Возвращать стабильные JSON-ошибки.

Проверка: интеграционные HTTP-тесты на успех, 404, некорректный запрос и недоступную базу.

## Этап 7. Эксплуатация
- Dockerfile (multi-stage build) и .dockerignore.
- Пример systemd unit или инструкции cron для импорта.
- Документация по первичному импорту, ежедневному 7-дневному обновлению, резервному копированию и WAL checkpoint.

Проверка: Docker build и smoke test в CI, документация проверена по фактическим CLI аргументам.

## Ограничение проверки

В текущем рабочем окружении нет установленного Rust toolchain. Поэтому локальные `cargo test`/clippy выполнить нельзя; CI в GitHub Actions будет обязательной проверкой каждого этапа. Если CI недоступен или падает, этап не считается завершённым.
